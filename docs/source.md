### Заголовки

Без заголовков сайта сервер отвечает `401 Unauthorized`. Токенов и cookie нет, сайт добавляет сам:

```
Accept: application/json
Referer: http://timetable.bsufl.by/
Origin: http://timetable.bsufl.by
X-Request-Origin: http://timetable.bsufl.by
X-Timestamp: <unix-время в миллисекундах>
X-Request-Id: <строка вида mwbvuq1c-1ovkmf6z2mypi>
```

Нужно ещё проверить, какие из них обязательны и принимает ли сервер новый `X-Request-Id`
(в проверке использовался тот же, что в браузере, `X-Timestamp` текущий).
Парсер должен вести себя вежливо: один-два запроса в сутки.

## Формат ответа

Массив **правил**, а не отдельных пар. Одно правило = «пара в день недели `dayNumber` в слоте
`lessonNumber` с `dateIn` по `dateOut`, по неделям `isEven`».

```json
{
  "idSchedule": 300044,
  "dateIn": "2026-11-02", "dateOut": "2026-11-08",
  "day": "Понедельник", "dayNumber": 1,
  "lessonNumber": 4, "timeIn": "13:00", "timeOut": "14:20",
  "discipline": "Методика препод. ин. яз.",
  "disciplineFull": "Методика преподавания иностранных языков",
  "disciplineTypeId": 2, "disciplineType": "Практ",
  "classroom": "А 411",
  "groupName": "307/2", "idGroup": 224003619, "idF": 202, "faculty": "ф-т ан. яз",
  "teacherF": "Чаплинская", "teacherN": "Екатерина", "teacherO": "Олеговна", "teacherNamePost": "пр.",
  "isEven": 2
}
```

### Поля и выводы

- `dateIn` / `dateOut` — границы действия правила. `dateIn` обычно понедельник начала периода, а не день пары. День недели задаёт `dayNumber` (1 = пн … 6 = сб).
- `isEven`: **1 или 2, 0 не встречается** — чётность недели. Проверено: `isEven = 1` для недель, у которых `(понедельник − 2026-08-31) / 7` чётно (31.08, 14.09, …), иначе `2`. Для правил на одну неделю (разница дат 6 дней) расхождений 0. Для периода в несколько недель пара ставится только в недели с совпадающей чётностью. Якорь `2026-08-31` (начало семестра) придётся обновлять; совпадает с чётной ISO-неделей (36-й).
- Слоты: 3 — 11:15–12:35, 4 — 13:00–14:20, 5 — 14:30–15:50, 6 — 16:00–17:20, 7 — 17:30–18:50.
- Типы: `1` Лек, `2` Практ, `4` Сем, `11` «уч. зан.».
- ФИО преподавателя разбито на `teacherF` (фамилия), `teacherN` (имя), `teacherO` (отчество); должность в `teacherNamePost`.
- В сентябре–декабре 2026 в ответе 92 правила (≈230–330 пар после разворачивания).

### Подводные камни для парсера

1. **Правила надо разворачивать в конкретные пары** (дата + слот) с учётом `isEven`.
2. **В одном слоте бывает несколько пар одновременно**: спецкурсы по психологии, из которых студент выбирает один (4 варианта с разными преподавателями), плюс пересекающиеся правила (например, лекция и «Информационный час» в один слот). Значит, `id` пары должен включать не только дату + время + предмет, но и тип, преподавателя и аудиторию, иначе домашки склеятся. Интерфейс должен показывать параллельные пары списком.
3. Правила перекрываются и меняются (разные периоды для одного предмета с разной аудиторией). `idSchedule` для `id` не годится: он меняется при пересоздании правил.
4. Расписание пока лежит только на 31.08.2026 – 03.01.2027, дальше не запрашивать.
