# CLAUDE.md — Расписание и домашние задания для группы

## Цель проекта

Сделать удобный веб-аналог университетского расписания (БГУИЯ) только для одной группы. Одногруппники видят расписание на неделю и могут записывать домашнее задание напротив каждой пары или предмета. Приложение должно быть простым, быстрым, красивым и в первую очередь удобным с телефона.

## Архитектура

- **Хостинг фронтенда:** GitHub Pages (только статика).
- **Расписание:** парсер на Python запускается через GitHub Actions по cron (раз в сутки и вручную через workflow\_dispatch), сохраняет результат в `public/schedule.json` и коммитит его в репозиторий.
- **Домашние задания и авторизация:** Firebase (бесплатный тариф Spark): Firestore (NoSQL) + Auth + Security Rules. Фронтенд обращается к Firebase напрямую через `firebase` SDK, с офлайн-кэшем на телефоне (IndexedDB).
- Своего бэкенд-сервера нет.

## Стек

- Фронтенд: Vite + React + TypeScript, Tailwind CSS. Сборка в статический бандл, деплой в GitHub Pages через GitHub Actions.
- Парсер: Python 3, `requests` (у сайта есть JSON API, HTML не парсим).
- База: Firebase Firestore. Админ-скрипты: Python + `firebase-admin` (только локально).

## Этап 1. Разведка сайта расписания

1. Открыть страницу расписания группы и в DevTools на вкладке Network найти, откуда приходят данные.
2. Если есть JSON/XHR-запрос, использовать его напрямую, HTML не парсить.
3. Если данные только в HTML, разобрать таблицу через BeautifulSoup.
4. Описать в `docs/source.md` URL, параметры (группа, неделя) и структуру ответа.

**Готово.** Результаты в `docs/source.md`. Сайт: `http://timetable.bsufl.by/` (только http, на https порт закрыт), JSON API `http://www.timetable.bsufl.by/api/api/groupschedule`, группа **307/2**, `idGroup = 224003619`.

## Этап 2. Парсер

- Файл `scraper/scrape.py`.
- Нормализованный формат вывода:

```json
{
  "group": "307/2",
  "updated_at": "ISO-8601",
  "lessons": [
    {
      "id": "стабильный хеш от даты+времени+предмета+типа+преподавателя (аудитория НЕ входит: она меняется, домашнее задание остаётся)",
      "date": "YYYY-MM-DD",
      "weekday": 1,
      "start": "08:30",
      "end": "09:50",
      "subject": "Название предмета",
      "type": "лекция | практика | семинар",
      "teacher": "ФИО",
      "room": "ауд."
    }
  ]
}
```

- `id` должен быть стабильным, чтобы домашние задания не терялись при повторном парсинге.
- Обрабатывать ошибки: если сайт недоступен или структура поменялась, не перезаписывать старый JSON, а падать с понятной ошибкой.
- Workflow `.github/workflows/scrape.yml`: cron + workflow\_dispatch, коммит только при изменениях.

## Этап 3. Firebase (Firestore)

Коллекция `homework` (документ с автогенерируемым id):

- `subject` string — название предмета
- `lesson_id` string | null — если домашнее задание относится к конкретной паре
- `due_date` string `YYYY-MM-DD`
- `text` string (до 2000 символов)
- `author_id` string — uid автора (= его ID вида `u03`)
- `created_at`, `updated_at` timestamp

Коллекция `members` (документ `members/{uid}`): `name`, `login`, `created_at`. Её создаёт только администратор.

Доступ (Telegram не используем):

- Каждому одногруппнику админ выдаёт личные **ID** (`u01`, `u02`, …) и **ключ**. Вход в приложении по паре «ID + ключ».
- Технически это Firebase Auth, провайдер Email/Password: почта служебная `<id>@schedule.invalid`, ключ служит паролем. Писем не отправляется.
- Управление участниками (локально, нужен сервисный аккаунт): `python admin/members.py add "Иванов Иван"` / `list` / `reset u03` (новый ключ, тот же ID) / `rename u03 "Имя"` / `revoke u03`. ID не переиспользуются, даже отозванные (иначе новый человек унаследует авторство чужих домашних заданий).
- `firestore.rules`: читать и писать могут только те, у кого есть `members/{uid}`; автора домашнего задания менять нельзя, удалять может только автор, редактировать любой участник.
- Конфиг веб-приложения Firebase (apiKey и т.д.) — через переменные окружения Vite и GitHub Secrets. Файл сервисного аккаунта и `admin/keys.local.csv` НИКОГДА не коммитить (они в `.gitignore`).

## Этап 4. Фронтенд

- Главный экран: неделя с переключением вперёд/назад; на телефоне — список по дням, на десктопе — сетка.
- Каждая пара: время, предмет, тип, преподаватель, аудитория и блок домашнего задания под ней.
- Добавление и редактирование домашнего задания прямо в карточке пары, с подписью автора и временем.
- Подсветка сегодняшнего дня и текущей пары.
- Уведомления вверху страницы: сайт университета недоступен (по `public/status.json`, его пишет парсер при каждом запуске, в том числе неудачном), расписание давно не обновлялось, нет сети, ошибки загрузки; ручное объявление через `public/notice.json`.
- Отдельный вид «Все домашние задания» с фильтром по предмету и дедлайну.
- Тёмная тема, PWA (можно добавить на главный экран телефона).
- Интерфейс на русском.

## Этап 5. Деплой

## Принятые решения (и почему)

- **Firestore, а не Supabase:** офлайн-кэш в браузере, нет своего сервера. Telegram Login не берём: нужны облачные функции (платный Blaze).
- **Вход по ID + ключ:** Firebase Auth Email/Password со служебной почтой `<id>@schedule.invalid`, ключ = пароль. Ключи выдаёт только администратор через `admin/members.py`.
- **Парсер:** запись API = правило (`dateIn..dateOut`, `dayNumber`, `lessonNumber`, `isEven`), разворачивается в конкретные пары. `isEven == 1` соответствует чётной ISO-неделе; согласованность проверяется на правилах из одной недели, при расхождении парсер падает (не врёт).
- **`id` пары** = sha1(`дата|начало|предмет|тип|преподаватель`)[:12]. Аудитория в `id` НЕ входит: она меняется, а домашнее задание не должно отвязываться. Параллельные пары (спецкурсы по выбору) показываются отдельными карточками с пометкой.
- **Домашние задания:** редактировать может любой участник, удалять только автор, автора менять нельзя (`firestore.rules`).
- **Фронтенд:** Vite + React + TS + Tailwind v4 (семантические токены в `index.css`, тёмная и светлая тема), шрифт Inter (кириллица, из npm, работает офлайн), SVG-иконки без эмодзи, container queries (`@container`) для узких колонок, PWA вручную (`manifest.webmanifest` + `sw.js`, без плагинов), демо-режим `VITE_DEMO=1` без Firebase.
- **Уведомления:** парсер при каждом запуске пишет `public/status.json`; `notice.json` для ручных объявлений; баннеры в `web/src/components/Banners.tsx`. `scrape.yml` коммитит статус даже при сбое и помечает запуск красным; `deploy.yml` запускается и после сбоя.
- **Терминология:** слово «домашка» не использовать. Везде «домашнее задание» (интерфейс, документы, комментарии). В коде имена английские (`homework`), коллекция в Firestore называется `homework`.

## Эксплуатация

- Парсер: GitHub Actions, cron 04:00 UTC и ручной запуск (поле `group_id` только для проверки сбоя). Локально: `python scraper/scrape.py`.
- Фронтенд локально: `cd web && npm run dev` (боевой Firebase через `web/.env.local`) или `VITE_DEMO=1 npm run dev`. Сборка: `npm run build`.

- Секреты Actions: `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID` (значения из `web/.env.local`, не из чата).
- Локальные секретные файлы (все в `.gitignore`): `admin/serviceAccount.local.json`, `admin/keys.local.csv`, `web/.env.local`, `users.md`.

## Подводные камни

- Сайт университета открывается **только по http**; на https порт закрыт. API без заголовков `Origin`, `Referer`, `X-Request-Origin`, `X-Timestamp`, `X-Request-Id` отвечает 401.
- Расписание на сайте опубликовано до 03.01.2027. При смене семестра или года парсер может упасть на проверке чётности: нужна ручная проверка (баннер «Сайт университета недоступен» покажет проблему пользователям).
- Коммиты от `GITHUB_TOKEN` не запускают другие workflow: деплой после парсера запускается через `workflow_run`.
- GitHub зарегистрировал `scrape.yml` с задержкой (после пуша при запуске был 404): помог новый коммит с правкой файла.
- Для пуша в `.github/workflows/` токену `gh` нужен scope `workflow`: `gh auth refresh --hostname github.com --scopes workflow --clipboard` (интерактивно, владелец вводит сам через `!`).
- `firebase deploy` без `"database": "default"` пытается создать `(default)` и падает с 403 (требует биллинг). В Admin SDK: `firestore.client(database_id="default")`.
- Service worker кэширует статику: после выкладки может понадобиться Ctrl+F5. Все `.json` берутся из сети.
- GitHub отключает cron в репозитории без активности 60 дней: ежедневный коммит `status.json` этому мешает. Не убирать.
- На машине Node 26: предупреждения `EBADENGINE` у `firebase-tools` безвредны.
- Автопрокрутка к сегодняшнему дню не должна прятать баннеры (решение принимается один раз на неделю и пропускается при наличии баннеров).
